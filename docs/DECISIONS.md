## DEC-0004：服务端会话与事务边界

- 来源：实施方自主决策。
- 问题：内部登录、任务重试与批次重复提交需要可撤销、可验证的状态。
- 依据：FastAPI 会话依赖与 lifespan 测试：https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/ 、https://fastapi.tiangolo.com/advanced/testing-events/ ；SQLAlchemy 事务与 PostgreSQL 冲突处理：https://docs.sqlalchemy.org/en/20/orm/session_transaction.html 、https://docs.sqlalchemy.org/en/20/dialects/postgresql.html（2026-10-05 经文档工具查阅）。
- 选择：随机会话令牌只在 HttpOnly Cookie 中，数据库保存令牌哈希，登出立即撤销；不用不可撤销的长效 JWT。批次幂等使用 PostgreSQL advisory transaction lock 与唯一键；每来源结果独立事务提交。
- 备选：仅浏览器保存登录状态；以内存字典保存运行状态；均不满足重启恢复和失效处理。
- 验证：登录、登出撤销、异源写入拒绝、批次幂等、公司隔离、部分采集不产生下架等集成测试通过。
- 影响：backend/app/security.py、tasks.py、ingest.py、models.py、初始迁移。
- 回退：可迁移会话实现，保留对外登录接口；数据和幂等规则不应因框架替换而弱化。
- 状态：已实施，待审计。

## DEC-0005：优先实现低成本模型网关

- 来源：用户指定 glm-5.3 优先、deepseek-flash 备选及 Chat Completions 协议；预算与测试防护细节由实施方决定。
- 依据：已读取 OpenAI Chat Completions 创建与流式事件参考：https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create 、https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events/（2026-10-05）。仅核对协议，不假定用户代理的计费或供应商扩展能力。
- 选择：默认每日最多 12 个请求、单任务最多 3 次、输入最多 16000 字符、输出最多 1200 tokens；发出请求前通过 PostgreSQL 锁原子预留预算。无自动重试、无自动模型切换。
- 备选：每个 Agent 直接调用接口；SDK 默认重试；均容易造成隐藏成本。
- 失败语义：超时按可能已计费处理，状态 unknown 仍占请求预算；未返回用量时保存未知。
- 测试：使用假密钥和 MockTransport；APP_ENV=test 时禁止不带模拟 transport 的真实调用。并发预算、超时次数、空 choices 的流式用量片段等测试通过。
- 已执行：网关与持久化调用记录；截至此记录真实模型调用 0 次，上游连通性未验证。
- 影响：backend/app/llm.py、config.py、test_llm.py、私有配置。
- 回退：预算可以由管理员按实际需求调整；不能未经记录移除限制或引入静默重试。
- 审计点：12/3/1200 是保守实施默认值，不是模型服务端配额或费用承诺。
- 状态：已实施，待审计；真实接入效果仍需有界验证。

## DEC-0006：处理本机合成 DNS，同时保留地址边界

- 来源：实施方自主决策，真实失败驱动。
- 问题：careers.tencent.com 在本机解析到 198.18.3.54，导致 SSRF 地址检查拒绝。直接 curl 能读取，但未经验证放行保留地址不合适。
- 依据：实际 socket 解析结果；Google DNS JSON 官方文档 https://developers.google.com/speed/public-dns/docs/doh/json；本环境 httpcore 对 sni_hostname 的实现。2026-10-05 已读取文档与实现。
- 选择：增加默认关闭的 PUBLIC_DNS_FALLBACK，仅当解析结果全部位于 198.18.0.0/15 时允许通过固定公网 DNS 服务查询 A 记录；结果仍必须全部是公网地址。
- 连接：连接到验证后的固定 IP，保留原始 Host 与 TLS SNI，按原始域名隔离连接池，每个重定向重新校验；不使用未验证域名的二次解析结果。
- 备选：全面关闭地址校验；直接放行所有私有地址；均拒绝采用。
- 验证：IP 固定与 TLS 主机名测试、私有/元数据地址拒绝测试通过；腾讯两条真实岗位采集成功。
- 影响：backend/app/collection.py、config.py、私有本地配置；部署默认仍关闭。
- 回退：关闭 PUBLIC_DNS_FALLBACK，改用能提供真实公网解析的运行环境。
- 审计点：启用后目标域名会发送给固定公网 DNS 服务；不发送模型密钥、账号凭据或岗位正文。
- 状态：已实施，待审计。

- 问题：SQLAlchemy会话不在commit后过期，行锁不能自动刷新旧ORM实体；旧恢复任务还可能在判断active之后，被并发新发布插入，再错误回滚新版本。活动ID即使A→B→A回到原值，仍不是原来的执行世代。
- 依据：两Session/barrier实测先得到4个失败：旧实体发布、发布ABA、自动回滚竞争和回滚ABA。不是基于假设新增复杂度。
- 决定：Registry增加 `release_generation`，每次切换活动版本递增；候选保存 `replaces_generation`。取得锁后强制刷新；发布及自动回滚同时核对ID和代次。旧候选缺代次时要求重新建立，不伪造历史。
- 已实施：迁移 `a918eb1a67d2`、统一activate函数、自动回滚调用及回归；冲突写 `rollback_skipped=release_conflict` 并保留失败记录。
- 验证：维护联跑55项通过，新增缺历史代次用例后CAS文件5项通过；本机Conda、独立测试库、0外网/模型。
- 回退：代次字段保留，不通过删除检查恢复旧竞争语义。未来代码包与JSON版本共用同一active指针和CAS。
- 状态：已实施，待审计。

补充审计（同日中央联调）：上轮两Session用例覆盖“读取当前版本后发生并发切换”；本轮另补“旧JSON恢复收尾前，A→B→A已经全部完成”。新真实数据库用例先失败，确认仅取收尾时当前generation仍会误回滚。现JSON恢复和代码恢复一样，保存原发布generation到事件与来源快照；准备恢复和自动回滚仅接受该原代次。历史缺失或快照错配时记录 `recovery_generation_missing`，不补造当前代次。新增正反例与旧自动维护35项通过；全量另行重新冻结，不沿用修复前结果。
