# P6/P7 采集链路复核、修复与真实来源证据

日期：2026-10-05（Asia/Shanghai）。本记录补充早期 `SENTIMENT_VALIDATION.md` 和 `NEWS_VALIDATION.md`，以本轮实际代码与证据为准。没有把 fixture 成功、HTTP 200 或网络失败当成外部平台正文采集成功。

## 1. 本轮发现并修复的实质问题

### 搜索结果没有进入详情，预算只限制入口数量

原实现只读取配置入口，不跟进搜索结果详情或下一页。现已：

- 只跟随页面中实际观察到的详情链接、`rel=next` 或明确“下一页”链接，不猜测帖子 ID 或翻页网址。
- 配置入口、搜索页、详情页、下一页共用同一个 `max_pages` 预算，失败的请求也计入尝试预算。
- 正文读取优先于继续翻页；保留 `attempted_pages`、`successful_pages`、`detail_pages`、`pending_pages`、`visited_urls`、`pending_urls` 和浏览器实际导航次数。
- 预算没有覆盖完的来源显示部分覆盖；只发现链接但还没读到正文时明确返回页面预算/内容不可识别原因，不报告“零舆情”。
- 已读内容在后续页面失败或时间预算到达时可以作为部分样本保存；取消仍尊重停止请求，不继续新网络操作。

### 登录重绑后重试还在使用旧账号快照

原重试复制旧 `account_id`，会在用户新增账号绑定后卡在 `source_changed`。现重试保留原对象、时间范围、来源选择与分析主题，但重新取得当前来源/账号配置快照，生成新任务；旧任务证据不覆盖。

账号会话仍来自统一登录中心，保存在加密状态文件中。登录、验证码由用户完成；代码不解验证码，也不推断“保存会话”就代表账号所有权或平台权限已验证。

### 浏览器二次 DNS 解析、错误页与账号跨域风险

原浏览器在 URL 校验后直接放行请求，未固定 Chromium 的域名解析，且忽略了部分 HTTP 错误。现已：

- 使用与 `BrowserCapture` 一致的预解析、固定 IP、未知依赖先阻止再重新启动的策略；每个放行域都提前校验为允许地址，浏览器不使用系统代理绕开固定解析。
- 最多12个依赖域、最多3轮依赖导航；调用者可进一步降低。真实匿名检查显式限定最多2轮。
- HTTP 401、403、429及其他400以上错误不会成为原文。
- 已保存会话只加载对应平台注册域的 Cookie 和 origin storage；账户页面主导航和子请求不能进入未登记平台域，也不允许 HTTP 降级或任意端口。
- WebSocket 不承载不受控的额外读取；媒体/图片/字体不为正文采集扩张流量。
- 已有可读正文但部分依赖没加载时保留内容并显示部分覆盖；不会为了成功而关闭地址保护。
- 账号范围内的临时浏览器状态可在同次来源读取中复用；不会把账号状态或访问令牌发送给模型。持久化账号状态仍由登录中心管理。

### 关键词可能把其他公司的投诉归入本公司

原实现只搜索 `keywords[0]`，并把名称、别名、关键词全部按 OR 用作归属。公司关键词若写“退款”，可能归入其他公司的退款帖子。现已明确区分：

- **实体归属**：泛搜索结果必须命中对象名称或别名；单独命中“退款/质量”等主题词不足以归属。
- **查询扩展**：依次构造对象名称、别名、`对象名称 + 主题词` 的搜索；不单独搜索泛主题词后全部归属公司。
- **有界轮询**：默认搜索来源在读取到实际内容后推进 `search_cursor`，后续任务从下一关注词开始；登录/网络门槛不跳过本词。每轮仍受原页面预算约束，没有扩大成全网抓取。
- `counts.search_queries` 保存每个查询词的 `page_read/not_attempted/失败原因`，报告覆盖中保留有限的已查、未查词摘要；不会将轮询样本当作同口径全量声量。
- 不能确认归属的原文不会悄悄作为本公司数据入库；`pending_attribution` 保留最多20个原文链接、标题和原因，供用户核对。

### 人工确认内容不应因没有公司名而全部丢失

现保留两种明确、可审计的人工归属：

- `user_import`：用户向一个对象明确导入的原文，可以没有公司名。导入来源真实性仍未独立核实，既有排除词仍有效。
- `user_selected_url`：用户显式声明一组单篇链接属于目标对象。只作用于直接选定的帖子/文章，不能配置为首页、搜索或栏目，也不扩展到从页面发现的其他文章。

`classification.attribution_basis` 保存归属依据，`attribution_verified=false` 明确未独立核实。默认仍是 `entity_match`。**目前没有实现“已验证企业官方账号所有权→其所有无名称评论均自动归属”的功能**；登录账号不是被监测企业的官方账号身份依据，未冒称支持 `verified_account`。

### 搜索摘录、视频文案与详情正文混淆

- `content_extent` 明确区分 `search_excerpt`、`detail_body`、`video_description`、`source_text`。
- `source_page_url` 说明内容从哪个页面实际取得；原文身份、页面来源及内容哈希均保留。
- 视频仅取实际可读文案或标准 `VideoObject` 描述，不冒充音频转写、图像 OCR 或完整视听分析。
- 详情页面中推荐的其他帖子，不会被当成当前选定帖子的正文。
- 公开正文仍可读、但评论区要求登录时，正文可以保留为部分样本；客户正文在抱怨“登录/验证码”也不会仅因这些词被当成登录页。
- 明确帖子身份的短评不再因为不足12字而一概丢弃；相对时间仍不猜测，微博明确携带时区的时间字符串可解析。

## 2. 接口变化

不需要新增数据库迁移，附加数据保存在已有 JSON 配置/分类/覆盖记录中。

| 接口/字段 | 行为 |
|---|---|
| `POST /sentiment/runs` 的 `render` | 省略或 `null`：按平台自动选择；`true`：浏览器；`false`：匿名来源仅HTTP。绑定账号使用会话浏览器 |
| `GET /sentiment/status` | 返回默认使用浏览器的平台、模式说明和预算范围 |
| `POST/PATCH /sentiment/sources` 的 `attribution_basis` | `entity_match`（默认）或显式 `user_selected_url`；不接受首页/搜索作为单篇归属 |
| `SourceRun.counts` | 原有数量之外，记录查询词状态、已读/未读链接、详情数、尝试数、待核对归属和浏览器导航数 |
| 原文 `classification` / 报告 evidence | `content_extent`、`source_page_url`、`attribution_basis`、未独立核实标记 |
| `POST /news/runs` 的 `render` | 可选布尔值，默认 `false`；只对 `web` 来源使用浏览器，Feed保持HTTP读取 |

主前端由主工程接入，本文不把后端字段存在等同于所有前端控件均已验收。

## 5. 回归范围与仍有限制

当前所属测试组 **103 项通过，6.61秒**；本轮新增 `test_sentiment_crawl.py` 共30个参数化用例。Conda环境为 `hr-research-dev`，回归数据库为独立 `hr_research_sentiment_test`。所属服务/API及新增测试的 Ruff通过。

重点覆盖：搜索→详情→下一页；失败也占预算；短评；公开正文与受限评论共存；视频文案标签；主题词不独立归属；人工导入/选定URL归属；推荐帖不混入；已查/未查词与轮询；登录后重新快照账号；时间预算保留已读样本；DNS固定；私网依赖阻止；错误页拒绝；Cookie/origin过滤；账号子请求和HTTP降级阻止；明确选择HTTP时不擅自启用浏览器。

仍明确存在的范围限制：

- 尚未验证三大社交平台真实登录后的最新 DOM/初始数据格式，不承诺所有账号和入口均可稳定读取。
- 无限滚动但没有可见下一页链接的更多结果未自动展开；预算以内的样本不等于全平台或全部关注词覆盖。
- 没有单独建设完整评论树、视频口播转写、图像OCR和实时传播网络；已获取文本和视频文案会明确标识。
- “已验证企业官方账号所有权”的归属流程尚未建设；未因一个可登录账号就把该账号页面的全部内容判定为目标公司。
- 未取得的互动量不补造为0；当前正文采集不承诺完整热度指标覆盖。

这些边界随任务覆盖和原文证据展示。本文没有把模拟用例、用户人工归属或 HTTP 200 当成未经证明的事实、归属或平台覆盖。
