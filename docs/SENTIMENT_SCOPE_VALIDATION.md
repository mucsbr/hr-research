# 舆情任务来源与时间范围：入口与页面验收

日期：2026-10-05（Asia/Shanghai）。补齐PLAN 4.4与11.3中已有后端参数但缺少页面入口的来源、时间范围选择。本轮仅修改 `frontend/src/SentimentPage.tsx`，新增专用UI验证脚本及本文；没有修改后端或执行真实采集/模型任务。

## 已核对的现有后端语义

| 模式 | 来源范围 | 时间范围 |
|---|---|---|
| collect | 明确选择的当前对象启用来源；留空为该对象全部启用来源，单任务最多20个 | 只过滤实际已读内容的已知发布时间；未知发布时间仍保存并计数。不是向平台承诺完整历史搜索 |
| analyze | 只读已有资料；明确选来源时取曾由这些来源采得的条目；留空包含该对象全部已有资料，包括人工导入 | 已知发布时间优先，未知则用首次发现时间；当前最多8条分析样本 |
| bettafish | 与analyze共用 `evidence_for_analysis`，不因选择范围重新采集 | 同analyze；许可、报告配置及模型预算仍由后端实际门禁处理 |

依据：`sentiment_api.RunInput`、`create_sentiment_task`、`ingest_documents`、`evidence_for_analysis`、`bettafish_bridge`的现有调用。区间允许只填开始或结束，边界包含；后端要求带时区并拒绝开始晚于结束。当前接口只接受属于对象、存在且启用的来源；没有来源的对象可以分析已有导入，但不能创建采集任务。

明确选择来源限制的是条目曾由该来源观察的身份，不保证主资料只来自那一次观察；界面用“曾由这些来源采得”表达，不误写成重抓来源全文。

## 页面改动

- 来源按任务表单所选对象独立读取，不沿用页面列表的对象筛选缓存。切换对象立即清空来源，已停用或其他对象来源不能选择。
- 来源留空的采集/分析含义分别说明；超过20个启用来源时要求选择本次范围。
- 开始、结束输入明确为北京时间UTC+8；由墙上时间字符串按固定偏移转为UTC提交，不依赖浏览器时区。允许单边界和空范围。
- 显示未知发布时间的模式差异，以及“采集过滤不保证平台历史搜索覆盖”“分析只读已有资料、最多8条样本”等限制。
- 取消后重开恢复默认任务类型、来源、日期、2页预算及自动渲染；不会带入上次未保存范围。当前页面已选且启用的对象可作为新任务默认对象。
- 反向区间、非整数或超出1—5的页面预算不发请求。分析主题限制为1—300字；不提交其他模式隐藏的无效预算或主题值。

数值验证中发现Ant InputNumber同时设置min/max可能保留旧合法值：测试输入0却提交旧2。改为由表单整数/范围规则校验，组件仅提供aria范围提示；不静默调整或使用旧值提交。

## 实际浏览器与接口契约验证

运行：

```sh
# 使用已有项目Conda和已安装Chromium，不安装或调用Docker。
conda run -n hr-research-dev python scripts/verify_sentiment_scope_ui.py --execute
```

脚本默认只显示计划；`--execute`才启动本机静态服务与隔离内存API夹具。使用真实构建React、真实Chromium及实际HTTP请求，每次任务请求交给生产 `RunInput.model_validate`；不会转发到实际API、连接数据库或运行Worker。

7组场景通过：

1. 采集选来源与页面预算；浏览器时区为America/New_York，北京09:30仍准确提交UTC01:30。
2. 对象切换清空原公司来源，新对象留空使用其默认范围。
3. 分析指定来源、只填开始时间，以及未知日期按首次发现时间的说明。
4. 仅导入对象不能采集，但可留空来源分析已有资料。
5. BettaFish提交相同来源/时间契约，只填结束时间；仅验证请求，不执行引擎或消耗模型。
6. 反向区间与0、6、1.5页预算均在请求前拒绝。
7. 取消重开清空未保存范围并恢复默认模式、预算和渲染。
