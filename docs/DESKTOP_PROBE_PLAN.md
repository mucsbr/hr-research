# Windows / macOS 桌面探针方案

状态：2026-10-11用户授权实现，服务端和Win x64/Mac Intel/Apple Silicon三个内部包已发布；实际证据和缺口见 [实施记录](PROBE_IMPLEMENTATION.md)。正式设备尚未配对，原生安装/真实Chrome及账号采集未验收，本文件仍保留完整目标。用户最新接受自签HTTPS和未签名内部分发，签名/公证不是首版阻塞。

本方案将桌面探针作为需要登录来源的主要接入方式。手工填写CDP保留为高级方式，替代上一版要求普通用户配置Chrome启动参数、调试端口及隧道的操作流程。平台业务范围仍为中国大陆公司内部招聘、整体舆情、HR资讯。

## 1. 总体选择

| 层次 | 选择 | 作用 |
|---|---|---|
| 用户端 | Windows/macOS常驻桌面探针，共用核心代码 | 安装、配对、Chrome管理、登录引导、在线状态及暂停 |
| 探针至平台 | 探针主动建立HTTPS/WSS连接 | 注册、心跳、接收命令、返回结果；不需要服务器反连终端 |
| 探针至Chrome | 本机loopback CDP，由探针自动配置 | 控制专用Chrome与持续profile；用户不填端口、不改路由 |
| 平台采集 | 既有任务/适配器通过浏览器提供器调用探针 | 正常采集依靠已验证程序；必要探索、维护与分析才调用模型 |
| MCP | 可选的服务端工具适配层 | 对平台智能体暴露浏览器能力；不承担NAT或远程连通 |

第一版推荐Electron/TypeScript桌面外壳及本机浏览器控制核心，使用系统已安装的Google Chrome。与现有Playwright采集技术衔接；不会用Electron内嵌WebView替代网站Chrome登录环境。服务端继续Python/FastAPI/Celery。版本按实际实现时的官方支持组合冻结，不凭未测试的最新版声明Win/Mac兼容。

不在用户电脑部署LLM、Python/Conda、Docker或开发工具。探针是确定性程序，不是一个每次点击都请求模型的聊天智能体。普通采集自动执行已验证的浏览器操作；生成的Python/依赖候选仍只在授权远端Runner执行，不能下载到用户电脑运行。

## 2. 非技术用户的操作流程

1. 在平台的“采集设备”页面下载适合Windows/macOS及架构的安装包，获取短期一次性配对码。
2. 安装并启动探针。服务器地址尽量由下载页预填或深链传入；普通输入方式仅需地址、配对码和可选设备备注。
3. 注册成功，探针显示“已连接”，Web显示这台设备及其能力/版本；授权与当前内部用户及设备归属绑定，不能只填URL就加入任意平台。
4. 在探针或Web选择BOSS/微博/小红书等平台，点击“打开Chrome并登录”。探针检查Chrome，自动使用自己的持久profile启动可见窗口。
5. 用户在真实Chrome里扫码、输入或处理验证码；点击“我已完成登录”后做有界、只读的登录/来源可读性检查。连接成功不代替登录成功，人工点击也不代替站点验收。
6. 来源账号绑定设备、profile、平台。明确该账号授权用于哪些公司招聘/舆情来源；真实公司页URL与公司身份仍需绑定，不能复用测试来源。
7. 以后从Web触发任务或启用已配置计划，平台选择已绑定的在线探针执行。用户不必每次配置CDP、重登或手工逐页复制数据；账号自然失效时重新引导登录。

登录在探针所在机器完成，采集也在同一Chrome/profile/网络出口完成。不导出Cookie后让服务器换IP再采集。用户提到的小红书300012可能与IP有关，但当前没有可复现实证；若本机Chrome人工访问也失败，探针应展示原限制并暂停，不宣称能消除风控。

## 3. 主动连接与命令通道

```text
探针主动发起：用户电脑 → HTTPS/WSS → 平台网关
任务下发：平台 → 已建立的连接 → 探针
网站访问：探针 → 本机Chrome → BOSS/微博/小红书
资料回传：Chrome → 探针 → 同一连接/受认证HTTPS上传 → 平台解析与入库
```

WebSocket连接建立后是双向的。终端在NAT、防火墙或无公网地址后，不影响服务器通过该既有连接发送命令；不是服务器另行连接终端的监听端口。若企业网络不支持WebSocket，可用有界HTTPS长轮询领命令、POST回执作兼容方式，复用同一认证、命令和幂等合同。

- 每台设备有独立可撤销凭据/密钥，配对码短期、单次兑换，绑定到明确用户。Windows使用DPAPI保护本地秘密，macOS使用Keychain；秘密不进入安装包、前端、任务日志或Git。
- 握手包含device ID、协议版本、探针/Chrome版本与实际能力。未知操作/字段拒绝，不能按字符串直接执行代码。
- 心跳与有上限、带抖动的重连；设备重启或网络恢复不创建重复任务、不重发已知完成的采集操作。
- 每条命令携带command ID、task ID、attempt/执行代次、profile/目标页、允许来源和预算；回执绑定这些字段，旧执行晚到不能写入新任务。
- 浏览器点击或导航结果未知时不盲目重放。先读取任务页与回执恢复状态；无法确认则标为需核实，保留原因与检查点。
- 探针可主动暂停、退出或解除配对。服务端支持撤销设备、停止下发；退出后不把其离线当解析失败，也不触发模型修复。

当前保留内网HTTP，另已发布`https://10.255.200.16:18443`及真实内部CA/SAN证书，公开CA随配对配置传入探针并正常校验TLS。用户接受自签HTTPS；配对配置须来自自己的平台，HTTP获取不等于公有CA身份认证。开发通道测试与正式网关核验分别记录，不要求终端开公网CDP或手工路由。

## 4. 浏览器与权限边界

- 探针作为登录用户的托盘应用运行。Windows使用交互用户会话，macOS使用用户级启动方式；不能把需要显示Chrome的登录功能做成无桌面的SYSTEM服务/系统daemon。
- 自动查找系统Chrome；缺少Chrome时明确引导安装。第一版不自动切换Edge、Electron Chromium或服务器无头浏览器。安装与更新资源必须在目标大陆环境可达，不依赖用户现场执行npm/pip下载开发依赖。
- 以探针自有数据目录建立持久profile。Chrome136+的非默认user-data-dir要求由程序处理；不占用、复制或杀掉用户日常默认Chrome。初次需在专用profile登录一次，后续复用。
- profile可保存多个不同平台的登录；同平台多个账号需要不同profile。平台来源账号与具体device/profile绑定，不能仅因另一台探针在线就擅自替换身份。
- 首版同一浏览器/profile只跑一个采集任务；人工登录和采集互斥。保留单公司底层任务、上层批次及有限并发；不同浏览器资源可并发。
- 仅操作任务创建或用户明确授权的Chrome标签页，只暴露导航、限定点击/滚动、读取指定正文/DOM、观察允许的业务响应、清理自有页等浏览器工具。
- 不提供通用Shell、任意文件系统、密码库、其他应用或完整桌面控制。站点登录表单、扫码令牌、验证码和无关浏览内容不交给模型，也不作为诊断截图上传。
- 不给服务器直接透传无限制的终端控制接口。若保留内部CDP透明桥，只能用于专用profile、受严格工具权限限制；首版优先结构化浏览器命令/结果。
- 不全局覆盖用户Chrome网络、代理、缓存、Service Worker或其他标签页的请求处理。任务完成仅关闭任务自有页和监听；不关闭用户普通Chrome。

## 5. 接入现有采集器

1. 引入统一浏览器提供器，区分服务器匿名读取、桌面探针、手工CDP高级接入；已绑定探针的登录来源不得静默换执行节点。
2. 招聘正常程序获得有界DOM/岗位响应、分页与详情资料；舆情搜索/详情同样通过探针浏览器读取。受限读取不等于“只能由模型看截图”。现有归一化、身份校验、入库、趋势与跨来源匹配继续在服务端。
3. 网站数据在本机Chrome发起正常请求；探针传回合同允许的业务资料。认证接口/请求头/Cookie/无关个人资料不上传，不能把整个profile或全部网络响应转存到服务器。
4. 现有Python采集器需要适配浏览器提供器和异步设备命令，不能简单把endpoint配置改一下就称为完成；两条招聘/舆情浏览器路径都要验收。
5. 已验证选择器/响应契约优先；页面变化使用脱敏证据触发既有维护Agent。候选继续远端Runner隔离，发布后仍是受预算约束的规则/可信执行；探针不执行模型临时生成的本机脚本。
6. 原来源/账号/公司快照、late-attempt门禁、页面/详情/时间预算、检查点及partial覆盖语义保留。离线/等待验证码不判岗位下架、不报“没有舆情”。

## 6. 服务端与Web新增范围

- 采集设备：下载安装、配对、在线/离线/暂停、版本能力、归属、当前任务、撤销、升级提示。
- 引导流程：设备就绪 → 打开Chrome → 平台登录 → 轻量确认 → 绑定正式来源 → 首次有限采集。
- 数据模型：device、device credential/key、browser profile、账号至device/profile绑定、命令与回执、执行lease；不把设备在线状态塞进来源是否已登录字段。
- 任务状态：waiting_device / waiting_login / waiting_verification / running / partial / failed分别解释；普通用户无需处理端口、CDP URL或协议字段。
- 断网、睡眠、Chrome关闭、未登录桌面用户会话、退出探针均能看到明确原因，保留进度。用户个人电脑不在线不能承诺24小时采集；定时任务可绑定持续在线且有可用桌面会话的专用机器。
- 用户通知仍使用已配置渠道/规则和冷却，不因同设备下多个公司任务反复发送相同离线提醒。
- 前端只连接平台API，不直接连接终端CDP或探针监听端口；平台代理授权与任务工具，不依赖当前聊天里的Codex在线。

## 7. 包装、交付与验收

交付是实际Windows/macOS安装包与完整业务链路，不只是协议示例或脚本。共用代码核心，各系统和CPU架构仍需实际安装/启动测试。用户明确接受未签名首版，签名/公证不阻塞本轮；卸载、用户级启动、升级后身份/profile保留继续保留为验收目标。当前包在Linux隔离交叉构建，不冒充原生验收。

- 使用Electron打包方式，首版按用户要求提供未签名内部包。系统单应用打开确认见安装说明；不宣称Gatekeeper/Keychain和企业策略已原生验证。未来签名可作为分发改进，不向用户重复索取首版签名证书。
- 不在当前用户电脑擅自启动开发环境、安装探针或开启CDP。本机仍只编辑源码；服务端测试在授权远端隔离环境。Win/Mac原生构建验收需明确可用的对应环境，不能用Linux测试替代。
- 服务端验证：注册单次兑换、认证/撤销、WebSocket及长轮询合同、心跳掉线、重连、幂等回执、旧执行拒写、设备/profile锁、取消/过期/预算。
- 探针验证：实际安装启动、Chrome发现/持久profile、不同系统路径、账号保持、断网/睡眠/重启、Chrome关闭/再启动、人工验证码暂停、用户原Chrome不受影响。
- 业务验证：招聘和舆情真实走指定probe的浏览器/出口；使用正式有界来源或独立QA库，业务原文、覆盖与入库可核对；不得在正式库制造新测试公司。
- 协议/模拟浏览器/真实Chrome/真实账号/真实站点可读性分别记录证据和源码范围。真正站点验收使用用户明确授权的目标和预算，默认真实模型请求0。

推荐顺序：注册/通道与设备管理 → Win/Mac安装及Chrome引导 → 浏览器提供器接线招聘/舆情 → 断线恢复与权限 → 原生安装/签名/真实站点验收。不会用设备已在线来签收后续业务采集或安装交付。
